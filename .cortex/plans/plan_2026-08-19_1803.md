## Context

**Key findings from exploration:**

1. **Bitdefender's dual nature**: The `PRODUCT_MANAGEMENT__ROYALTIES` table serves as BOTH the vendor-side (what CW owes BD, via contract rates) AND the CW billing side (via `original_amount_document`). Currently the pipeline uses `THIRD_PARTY_RECON_VENDOR_USAGE_PROD` (which is just the royalties data restructured) vs Zuora BillRun + CARR Marketplace. This creates confusing mismatches because Zuora includes MDR bundles that aren't in the vendor-side view.

2. **Current state**: 97%+ CLEAR rate, but the flags are non-standard (`CLEAR|MAT_LOW|SRC_...` composite strings) and don't match your requested unified flag taxonomy.

3. **Data sources available**:
   - `PRODUCT_MANAGEMENT__ROYALTIES` - primary source (both CW billing via `original_amount_document` and vendor cost via contract rates)
   - `ZUORA_THIRD_PARTY_RECON_BASE` - Zuora BillRun (independent CW billing validation)
   - `CARR__ALL_TRANSACTIONS` - Marketplace/NetSuite-Evergreen billing
   - `THIRD_PARTY_TRT_MONTHLY` - TRT API usage (~31k qty/mo, 85 partners)
   - Vendor portal export ingested as `THIRD_PARTY_RECON_VENDOR_USAGE_PROD` (~4.4k qty supplement)

4. **Match quality**: For June 2026, 399/479 matched accounts have EXACT quantity match between royalties and Zuora. The 64 "Zuora higher" accounts are explained by MDR bundle billing in Zuora that isn't a line item on the royalties report for those accounts.

  - Same source rows, but pricing from `BITDEFENDER_CONTRACT_RATES` (what CW owes BD)

- **Zuora BillRun** (`BITDEFENDER_BILLING_MATCHED`): Keep for validation/duplicate detection
  
- **Marketplace CARR** (`BITDEFENDER_MARKETPLACE_BILLING_MATCHED`): Keep for duplicate detection

- **TRT API Usage** (`BITDEFENDER_TRT_USAGE`): New table joining TRT data via CMS_ID → SF_ID for the "Missing CW Billing - API Confirmed" flag

### Step 3: Rebuild `02_final_reconciliation.sql` - Unified Outcome Flags

**Reconciliation grain**: (sf_id, billing_month, sku_match_group) — product-level, not just partner-month

**Join logic**:
1. CW Billing (from royalties `original_amount_document`) → the "what CW billed" side
2. Vendor Cost (from royalties qty × contract rates) → the "what CW owes BD" side  
3. Zuora BillRun → independent validation, duplicate detection
4. Marketplace CARR → duplicate detection
5. TRT API usage → API-confirmed usage validation

**Unified outcome flags** (in priority order):
1. `Unmapped SKU` — SKU not matched on either side, still generating billing
2. `Duplicate Billing` — Marketplace AND Zuora billing the same account/month/sku_match_group
3. `Missing CW Billing - API Confirmed` — Non-null TRT API usage but CW billing = 0
4. `Billed by Vendor, Missing CW Billing` — Vendor cost > 0 but CW billing amount = 0
5. `Billed by CW, Missing Vendor Billing` — CW billing > 0 but vendor cost = 0
6. `Overage` — Partner billed, but CW qty < vendor usage qty
7. `Vendor Billing > CW Billing` — Vendor amount > CW amount, both > 0
8. `Clear` — Quantities match within ±5% AND CW amount ≥ vendor amount
9. `Other Issue` — Catch-all for anything not matching above patterns

**Output tables**:
- `BITDEFENDER_RECON_DETAIL` — Full detail with all flags, deltas, amounts
- `BITDEFENDER_RECON_SUMMARY` — Monthly rollup by flag
