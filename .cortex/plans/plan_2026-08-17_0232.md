## Context

The standalone combined pipeline (`95_standalone_reconciliation.sql` + `sql/vendor/*.sql` + `90_vendor_router.sql`) already has a well-designed architecture but produces dramatically worse results (1-80% clear) vs individual pipelines (70-97% clear) because of 3 root causes:

1. **UNMAPPED billing SKUs** — `05_unified_billing.sql` produces 2,502 UNMAPPED rows for Bitdefender and 1,277 for ESET. These are CW-side billing SKUs (`CU-BITDF-*`, `3PARTYONPREM*`, `2765*`) that the SKU seed doesn't cover because it only maps vendor-side products.
2. **Canonical taxonomy not applying noise floor** — The `90_vendor_router.sql` uses the old taxonomy (INTENTIONAL_DISCOUNT separate from CLEAR, no noise floor, CONTRACT_BELOW_COST overriding resolved rows).
3. **Vendor override files are passthroughs** — `sql/vendor/proofpoint.sql` just does `SELECT * FROM GENERIC WHERE vendor = 'Proofpoint'` with no Proofpoint-specific logic.

## Implementation Steps

### Step 1: Fix UNMAPPED billing in `05_unified_billing.sql`
Add Bitdefender and ESET CW-side SKU patterns to the `zuora_with_group` CTE. For Bitdefender: map `CU-BITDF-*` → sku_match_group based on the individual pipeline's pattern, map `3PARTYONPREM*` → 'ENDPOINT', map `2765*` → detect from charge_name. For ESET: use the existing charge_name CASE WHEN (already there but only fires as fallback — the issue is the sku_lookup join produces a match to an incorrect group).

### Step 2: Port taxonomy improvements to `90_vendor_router.sql`
Copy the canonical_outcome CASE logic I built in `90_unified_reconciliation.sql` into `90_vendor_router.sql`:
- INTENTIONAL_DISCOUNT → CLEAR
- CONTRACT_BELOW_COST respects individual CLEAR
